# Project Submission Specification (V1)

## 1. Context and Philosophy

This platform aims to connect local initiatives around the world with international organizations, experts, volunteers, technical partners, universities, companies and donors.

The project is based on the following principles:

* promote bottom-up approaches rather than top-down development models,
* give visibility to local realities and local expertise,
* facilitate ethical and sustainable collaborations,
* mutualize human, technical, financial and material resources,
* create long-term partnerships centered around local needs.

The goal of this platform is not to impose external solutions, but to help local actors present their realities, projects and needs in a structured and accessible way.

This document defines the first version of the project submission specification.

The V1 focuses on simplicity:

* no automation,
* no complex moderation system,
* no user dashboard,
* no automatic project publication.

Projects are manually reviewed by a human before publication on the platform.

---

# 2. Objectives of the Submission Form

The submission form should allow project holders to:

* present their initiative clearly,
* explain the local context and needs,
* describe the expected impact,
* specify the type of support they are looking for,
* provide contact and verification information.

The collected information will allow the platform team to:

* understand the project,
* contact the organization,
* verify legitimacy and coherence,
* potentially ask additional questions,
* manually decide whether to publish the project on the platform.

---

# 3. V1 Workflow

## Step 1

A project holder submits the form through the website.

## Step 2

An email containing all submitted information is sent to the platform team.

## Step 3

A human reviews the submission manually.

## Step 4

The team may:

* contact the organization,
* ask for additional information,
* request documents or clarifications,
* organize a call if necessary.

## Step 5

If validated, the project is manually added to the website and the interactive map.

---

# 4. General Principles

The form should:

* remain simple and accessible,
* avoid overwhelming users,
* work well on mobile devices,
* prioritize clarity over administrative complexity.

The form should collect enough information to:

* understand the project,
* assess credibility,
* facilitate future collaborations.

The form should avoid:

* excessive bureaucracy,
* unnecessary technical language,
* overly rigid requirements.

# 6. Human Validation Process

All projects submitted through the platform are manually reviewed.

The platform team may:

* verify project coherence,
* request additional information,
* contact the organization,
* organize a discussion or video call,
* refuse projects that do not align with the platform values or quality standards.

Submitting a project does not guarantee publication.

---

# 7. Publication Rules

If validated, projects may later appear:

* on the interactive map,
* on a dedicated project page,
* in thematic categories,
* in partner searches and future collaborations.

The platform reserves the right to:

* edit formatting,
* improve readability,
* request additional verification,
* refuse publication.

The original meaning and context of the project should always be respected.

---

# 8. Technical Notes for V1

The first version should remain intentionally simple.

V1 technical workflow:

* a website form,
* submission by email,
* manual review process,
* manual publication.

No automation is required for the first version.

Future versions may later include:

* databases,
* dashboards,
* project moderation systems,
* automatic workflows,
* matching systems,
* multilingual support,
* project verification badges,
* advanced filtering and search.

---

# 9. Notes for Claude Code (Future Implementation)

The future form page should:

* be mobile-first,
* use a clean and modern interface,
* prioritize readability,
* use progressive sections,
* avoid overwhelming users,
* support file uploads,
* support long-form answers.

The form should eventually generate:

* structured project pages,
* project previews,
* interactive map entries.

The V1 should prioritize simplicity, usability and trust.
